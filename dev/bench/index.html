How to read these measurements

Payload · prepared runtime is the primary timing scope. It includes workload class/object construction, execution, boundary calls, correctness checks and execution-time GC. Parsing, warmup, seed construction/installation, initialization GC, platform assembly and VM creation are outside the timer. Each payload uses a fresh independent world exactly once; batch timing amortizes clock overhead without accumulating exported objects in a reused world. Scores are normalized per payload operation. Batch sizes are shown and retained as separate measurement configurations.

Runtime initialization measures warmed world/VM setup separately. Fresh world + payload retains the original complete-workload series and new controls. These scopes are never joined into one graph or subtracted from each other. The prepared-runtime series starts a new baseline; a change of timing scope is not a speedup. JVM/process launch is excluded from all JMH scores.

Fixture creation outside the payload timer still affects Java GC and caches. GC allocation-profiler values can include fixture allocation; they are not payload-only allocation figures. Python and VarioHyve have different setup, lookup and boundary costs. Python interpreter/context initialization is outside its workload timer. GraalPy runs on the JVM with guest JIT disabled; Java compilation remains enabled.

Each point is one benchmark run. Branches share the timeline in measurement order; adjacent points can come from different branches and do not imply Git ancestry. Select a branch to follow its own history. Hosted runner hardware can vary.

Dots show means. In the spread view, boxes show the middle 50% of measured iteration means, the bar shows the median, and whiskers show the observed minimum and maximum. These describe iteration averages, not individual-operation latency or confidence intervals. Quartiles use linear interpolation across sorted samples. JMH's 99.9% confidence interval, when available, is shown separately in point details.

Older records have no samples and show a mean only. Their Python times (≈) are recovered from tooltip values rounded to three decimals; archived ratios retain their original precision. Missing data stays missing. Historical measurements before the explicit tracing profile are kept in a separate GC profile. Untagged historical runs are classified as fresh world + payload; prepared measurements require an explicit scope and batch size.

Sample distributions appear as workflows using the updated publisher complete. The raw download includes both the original archive and the new sample records.
