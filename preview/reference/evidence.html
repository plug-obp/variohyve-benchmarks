Release evidence and its limits

The public preview downloads contain the Java implementation, its starter, packaging tools and VS Code extension. The Lean native implementation and proof development are maintained separately; this release does not offer a Lean binary. The conformance map separates the language contract, Java regressions, cross-VM comparisons and scoped proofs.

What the proof results cover

Result family Meaning and premises
Native source adequacy For admitted source, a valid source configuration, a supported literal translation and the stated source/native representation relation, lowering preserves and reflects termination and relates divergence. Source-backed retained histories additionally require retained catalogs, compatible worlds/registries and sufficient frontend and execution budgets.
Immutable reference observation After initialization has settled, a realized immutable slot retains its reference through admitted source steps. Heap correspondence relates the source cell to its physical representation. This does not freeze the referenced object.
Immutable references after collection The same observation holds for a receiver retained by a supported collector graph, with explicit heap/address correspondence and liveness. Unreachable objects may be collected.

Validation identity

The release manifest records the runtime tag and full source commit, artifact byte sizes and SHA-256 hashes, toolchains, commands, results and platform scope. A later documentation or harness correction has its own revision; it does not change the identity of an already published binary. Test totals belong to the named revision and module set, not every version of the project.

The release checks use these entry points:

python3 scripts/check-docs.py
python3 scripts/check-learn.py --source-only
bash scripts/check-bootstrap.sh
bash scripts/check-lean.sh
./gradlew test
python3 scripts/check-starter-package.py
python3 vh-packaging/scripts/check-user-journey.py
python3 vh-packaging/scripts/check-user-journey.py --custom-alien

The assembled ZIP/VSIX gate additionally checks public help destinations, matching versions, installed Markdown links, licenses and the runtime JAR. The extension has separate typechecking, unit tests and an installed-editor journey. Only checks actually run for a release are recorded as passing.

Boundaries and open work

  • Java uses regression and differential evidence; no formal Java refinement is claimed.
  • Native library laws depend on their representation and callback contracts. VM proofs do not certify arbitrary libraries, worlds or foreign adapters.
  • Complete Alien/Expat source adequacy and general resource bounds remain open obligations. Existing budget/resumption results are not general time or memory bounds.
  • Lean's kernel, compiler and runtime are accepted infrastructure trust boundaries.
  • Platform status is specific to OS, architecture and test scope. CLI checks do not imply editor checks, and one platform's pass does not certify another.
  • Benchmark histories may measure different revisions from the downloadable preview. Timing scopes include their stated setup, transport and GC costs; they are not isolated VM-instruction costs or universal speed rankings.

The verification roadmap keeps deferred obligations distinct from established results.
