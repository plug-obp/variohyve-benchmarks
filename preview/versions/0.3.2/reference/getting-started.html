From a module to a deployed application

Install Java 23 or newer. Download the variohyve-packaging-*.zip for your platform from the public release downloads and extract it anywhere. The archive contains the launchers, native recipes, packaged capabilities and this example. No checkout, Gradle, Node or package-registry credentials are needed to use it.

Command line

Use absolute paths in these commands. On Windows use the .bat launchers and your shell's equivalent of copying a directory. VH below is the extracted installation and PROJECT is a writable copy of its examples/project folder.

export JAVA_HOME=/path/to/jdk-23
VH=/path/to/extracted/vh-packaging
PROJECT=/path/to/my-project
cp -R "$VH/examples/project" "$PROJECT"

Write your module in Main.vh. It receives a multiplier through an explicit input. World.vh constructs the independent native package at packages/multiplier/Multiplier.vh with factor 3, then imports the application. Change the module, its native dependencies and Tests.vh together as your application grows. The lib folder contains native SUnit dependencies. SuiteReporter.vh reports assertion details through its explicitly supplied console. The test entry loads these development sources lazily; the run entry does not require them, and Package.vh omits them from the deployment. The aliens folder contains the selected startup adapter and console; the sidecar sets alienRoot to this project. The native policy captures these project-owned packages. To add a provider that VarioHyve does not ship, follow Bring your own Alien package.

"$VH/bin/vh-world" "$VH" "$PROJECT/Main.vh.launch.json" --test
"$VH/bin/vh-world" "$VH" "$PROJECT/Main.vh.launch.json"

The test prints PASS and exits 0. Changing the expected answer from 42 to 41 prints supplied multiplier: Expected 41 but got 42, then FAIL, and exits 1. Restore 42 before continuing. The run waits for a line of input; enter Answer and it prints Answer: 42. End of input prints 42. A failed assertion returns false; a raised execution failure aborts the native suite. The starter vh test runner has a separate per-case recovery/reporting contract; this recipe does not inherit it.

Main.vh.launch.json selects the native world, run and test messages, startup adapter and stream grants. It also selects Package.vh, the native packaging policy. That policy explicitly declares every source and provider, pins the installed runtime ingredients and selects the deployed startup and message. When changing startup or entry points, update both the development selection and the native deployment policy. They use the same startup contract; deployment policy can deliberately select a different entry. Imports do not automatically add files to a deployment. Optional execution: {"maxSteps": 1000000} in the sidecar sets the budget for each independent VM entry; nested imports and callbacks share that budget. Omission uses 100000. Set output.execution(1000000) in the native packaging policy when the deployed world needs that limit too.

"$VH/bin/vh-package" "$VH" --launch "$PROJECT/Main.vh.launch.json" /path/to/new-application

The destination must not exist. Copy the resulting directory to another location or machine with Java 23+. It includes both Unix and Windows launchers. Run:

/path/to/new-application/bin/vh-deployed /path/to/new-application

Enter Elsewhere; it prints Elsewhere: 42. This launch needs neither the tools installation nor the source project. Keep the package intact: declared files are checked against their captured SHA-256 digests before execution. Files merely placed next to a package are not additional dependencies.

VS Code

Install Java 23+ and the matching VarioHyve VSIX from the same release downloads. The VSIX already includes the packaging distribution. In a trusted workspace:

  1. Run VarioHyve: New Recipe Project and choose a new folder. It opens Main.vh.
  2. Edit the module, World.vh and Tests.vh. Open Main.vh and use Test File; its adjacent sidecar selects the native test entry. Read PASS/FAIL and the exit status in the terminal. Run File uses the run entry and accepts terminal input.
  3. Use Package Application and choose a new output folder. The native policy runs in a terminal and reports the published path or failure.
  4. Move or copy that folder, then use Run Deployment to select it. This uses the deployment's own runtime and does not need the original project.

Recipe commands save open dirty VarioHyve files under the declared source root, check launch revisions, and support Stop Program. Runtime errors from imports are reported against the matching open source revision. Ordinary Run treats false as a valid result; Test requires a declared test entry returning a Boolean. A recipe sidecar grants no implicit JavaHostKernel input. Editor API assistance remains conservative for custom recipe inputs and startup adapters.
