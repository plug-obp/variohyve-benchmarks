Call VarioHyve from Java

An existing Java application can use a VarioHyve module as a component. calculator.vh exposes twice(value), which returns value.times(2). There is no required run method when Java chooses the entry message itself.

Read Embed.java. The important steps are:

  1. Create JavaHostKernel with the input and output streams the application owns.
  2. Call kernel.newRuntime() to select the Host Seed and its receiver protocols.
  3. Read a source snapshot and pass its name, text and constructor arguments to runtime.instantiateModule.
  4. Send calculator.send("twice", 21L) through the returned VHExpat.

An Expat is a VarioHyve object exposed to Java through messages. In this example the result returns to Java as a Long with value 42.

From the starter's learn directory:

mkdir -p out
javac -cp '../lib/*' -d out examples/java/Embed.java
java -cp 'out:../lib/*' Embed examples/java/calculator.vh

On Windows PowerShell, create out with New-Item -ItemType Directory -Force out and use "out;../lib/*" for the Java classpath.

twice(21) = 42
Failure: LANGUAGE_FAILURE / UNRESOLVED_HOLE
Source: calculator.vh

The last two lines demonstrate a call to the intentionally unfinished method. The Java client checks failure.kind() and failure.diagnostic().reason(); the diagnostic also records the source location from the snapshot we supplied. Use those fields to handle failures, rather than comparing error messages.

The 100_000 argument bounds module construction. Subsequent VHExpat.send calls use the runtime's default entry budget; that construction argument does not configure every later call.

You have now written programs, made objects, checked their behavior and connected both sides of the Java boundary. Try adding a second operation to the calculator, then add a test and call it from Java.
