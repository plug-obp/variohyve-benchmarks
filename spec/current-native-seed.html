VarioHyve Language Specification

One Possible Native Seed

The repository’s Current Native Seed module is one library choice. It is an ordinary isolated module whose sole constructor input is a narrow host identity service. The module stores that service in its _vm slot because constructor parameters are not method bindings. Its members and ordinary object literals implement the native canonical values and root behavior. The provider module has state; the Object it supplies has none.

The builder sends null/0, true/0, false/0, then Object/0, once each. The returned Object class initially inherits the provisional structural root. After validation, adoption removes that superclass edge, redirects the provisional root and scalar references throughout the retained graph, retires obsolete bootstrap ownership, and collects. The provider’s Object is then the actual root; its methods keep their original definition scope. No duplicate ancestor Object or forwarding wrapper is retained.

This module supplies the following protocols:

Null and Booleans inherit Object’s methods. Object delegates identity operations to the supplied service over the ordinary Alien/Expat boundary. Its methods are overridable client defaults, not VM instructions; independent observations use an explicitly supplied IdentityMirror. No number, string, or collection class is supplied by this module.

Boolean branch methods execute as native methods. A thunk that returns to an accessible native home does not cross foreign execution merely because its receiver is a canonical Boolean. If that thunk or its caller invokes foreign code, the boundary’s return-transfer agreement still applies. The current Java agreement forbids non-local return through an active foreign call; using this native seed does not disable that barrier.

With the compatibility Java codec, these three native identities cross as host null, Boolean.TRUE, and Boolean.FALSE; incoming host values recover the same native identities. Classification uses exact identities, without sending methods or recognizing names. Supported integral values and strings use the existing by-value transport. This conversion profile is a world choice, not a requirement imposed on all possible seeds.

Number/string transport is selected before the provider executes and stays consistent across adoption. Canonical null/Boolean conversion becomes active after the replacement commits, so bootstrap provisioning does not depend on the native roles already existing.

The source module records this library’s contract. Another provider may offer other methods or return Aliens for the scalar roles, provided it satisfies the structural and atomic-installation invariants. Missing library methods fail when sent; the machine does not preflight a Boolean or null protocol.

To load the checked source module through the public Java bootstrap API:

String source = Files.readString(Path.of("vh-source/bootstrap/current-native-seed.vh"));
var runtime = BootstrapRuntime.fromNativeSeedModule(
        source, BoundaryProfile.NATIVE_VALUES, Map.of());
Object result = runtime.evaluate("false.not", 1_000); // Java Boolean.TRUE

The convenience entry explicitly supplies the module’s narrow identity service. For a different provider ABI, fromSeedModule(source, profile, capabilities, inputs...) supplies exactly the listed constructor inputs. Tooling capabilities are assembled after seed installation, so they are not ambient module inputs.
