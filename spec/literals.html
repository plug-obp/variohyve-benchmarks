VarioHyve Language Specification

Literals

The literal forms are numbers, strings, holes, lambdas, classes and objects. Class and object syntax is defined in Objects and Classes; this chapter owns scalar syntax, closure returns and initializer completion.

null, true and false are ordinary source names, not literal forms. Their occurrences are message sends under name resolution. Canonical null for omitted initializers or empty bodies is supplied directly by the language; it does not depend on a declaration named null.

Operational definition: SOS evaluation and return rules.

Number Literals

numberLiteral : '-'? NUMBER ;
NUMBER        : NATURAL ('.' NATURAL)? ;
fragment NATURAL : [0-9]+ ;

Examples: 42, -7, 3.14159 and -0.5. Numbers use decimal notation; arithmetic and comparisons are messages such as x.plus(1) and x.greaterThan(0). The syntax does not settle the numeric domain, precision or overflow behavior. The prototype’s supported subset is documented under implementation limits.

String Literals

Single and double quotes produce the same runtime kind of value. Both support:

\\Backslash
\", \'Double or single quote
\/Slash
\b, \fBackspace, form feed
\n, \r, \tNewline, carriage return, tab
\uXXXXUnicode escape with four hexadecimal digits
 
"hello"
'it\'s fine'
"line one\nline two"
"\u0041" // A

Multi-Line Strings

Raw newlines are allowed inside either quoted form. They preserve all whitespace between the quotes, including indentation; "a\nb" and the corresponding two-line literal have the same content. See the lexer in vh.g4.

Hole Literals

? is an explicit incomplete expression, valid wherever an expression is expected. It has its own AST node and differs from both an omitted initializer and canonical null. A missing initializer supplies null; a hole remains unresolved.

Descriptors on Holes

Use parenthesized descriptor syntax, for example (? : expected(Controller) : reason("integration input")). Descriptors can inform diagnostics or a separately selected analysis tool; they do not silently change raw execution.

Runtime Semantics

A hole supplies no normal value by itself. Reaching it must invoke the execution context’s explicit hole policy. The concrete bootstrap reports UnresolvedHole. Interactive suspension, externally supplied replacements, abstract values, branching and synthesis are possible richer tooling policies, not implemented guarantees. Their interpretation must be specified by that context; accepting partial syntax does not imply an abstract interpreter.

Hole Identity

Each syntactic occurrence denotes a distinct hole. Tools should retain a stable internal identity, normally based on AST/source identity, for diagnostics, annotations, filling, traces or replay. A descriptor-supplied name or qualified source path may identify a hole to a tool. Two occurrences of ? do not become one hole merely because their spelling is equal.

Lambda Literals

fun and λ introduce lambdas. Parentheses around the parameter list are optional when it is empty. Bodies are semicolon-separated statement lists; an empty body and a trailing semicolon are allowed.

fun { 42 }
fun(x) { x.plus(1) }
λ(x, y) { x.plus(y) }

A lambda captures its evaluation scope, current receiver, contribution origin and lexical return home. It does not capture its later caller’s scope. Captured activation data can outlive the creating invocation. A lambda supplies exact apply/N at its declared parameter count; binding invocation uses the ordinary eligibility rules. Optional descriptors follow the closing brace.

A lambda is a native object with its own identity and the inherited root Object protocol. Distinct evaluations create distinct objects. Object-method sends use the lambda as receiver; its apply/N body instead uses the captured receiver and return home. Inheritance neither changes lexical self nor exposes captures. There is no public Lambda factory or ambient Lambda binding; the private representation is described in Core Structures.

Implicit Return

Methods and lambdas return their final expression’s value on normal completion. An empty body returns canonical null. This normal result returns from the current invocation; it does not perform a non-local return.

Early Return with ^

^ expression first evaluates its operand, then returns to the lexically enclosing method or initializer home. Lambda invocation creates no new home.

Creation contextTarget of ^
Method body or a lambda created thereThat method invocation
Initializer or a lambda created thereThat initializer contribution invocation
Supplied outside lambdaIts original home, even when called during construction

A missing or retired home causes a dead-context error. Captured data does not preserve return authority. A return crossing foreign execution is governed by the boundary agreement. The default agreement requires a live home reachable without crossing an active Alien callback barrier; supporting agreements must preserve these native home and initializer rules. Successful unwinding retires intervening invocation homes. Operand failure propagates as failure rather than completing a return.

Class expressions retain definition-time bindings, but each later initializer invocation creates a fresh home. An outside lambda can unwind construction to its own live accessible home; it is never rebound to the initializer.

Class Literals

The class keyword creates a named or anonymous class value. See class literal syntax and the distinction between member declarations and class expressions.

Object Literals

{ body }, optionally prefixed by mixin and superclass clauses such as <: M(p) < S(q) { body }, realizes a fresh anonymous zero-parameter class and immediately sends its primary new/0. It has no constructor parameter list or factories; contributor arguments and initialization follow the class rules. See object literals.

Initializer completion

A class or object body may end with | and an optional ordinary statement list. This section executes after that contribution’s ordered slot initializers:

class Config(input) {
    saved = input;
    value { saved }
    |
    ^ "done"
}

Primary construction returns the allocated receiver, not "done". No member, method, factory or slot declarations follow the delimiter; ordinary statements, including var and class expressions, are allowed. An empty | section is valid.

Descriptor lists also use |. Terminate a preceding described member, method or factory with ; to separate post-slot code: value { saved } : Tag; | performWork.

Each contribution invocation has a fresh private return home:

  • Slot phase: returning to that home is an error, including during the final slot expression. The phase ends only after its final value is written.
  • Post-slot phase: normal completion or ^ value completes that contribution and ignores the value. Subsequent contributions still run.
  • Every exit: normal completion, early return, failure and unwinding retire the home. Escaped data remain usable without retaining return authority.

Constructor parameters are visible in both initialization phases, under the construction scope rules. An outside lambda retains its original home. The default Alien callback barrier remains in force; any future crossing support must preserve these initializer phase restrictions. Failures neither replay initialization nor roll back effects or retract an escaped receiver. See the accepted policy.
