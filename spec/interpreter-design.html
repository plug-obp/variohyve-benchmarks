VarioHyve Language Specification

Java Interpreter

VisitorSemanticsVM is the executable prototype. The older VM is not a semantic authority. This chapter records how Java realizes the language contracts and formal reference machine, including implementation restrictions. It does not claim a completed refinement proof.

Machine Components

The CESK-inspired configuration is Configuration(control, environmentRef, runtimeWorld, continuationRef). The scope reference identifies an activation or lexical receiver view; RuntimeWorld supplies the store, boundary and seeded identities. There is no separate environment namespace.

Control distinguishes expression evaluation, exact host send, committed foreign call, returned value and error. EvaluateStepVisitor handles expressions; ContinuationStepVisitor handles completion; ObjectProtocol selects and invokes operations. Its ordered loops, getterSeen, Selection and EligibleAccessor retain lookup evidence without repeating reads or selection. The language algorithm is specified in Message Sends.

The step API returns a set, but the concrete driver requires exactly one successor for each nonterminal native configuration. It stops at an error or a value under HaltFrame. Observable determinism additionally depends on supplied foreign behavior. A set-valued interface does not implement abstract execution. Retained or prepared configurations do not each hold execution authority. All ordinary entry and stepping paths for one runtime obey the same sequential control agreement. step acquires admission for its selected configuration, advances one transition and yields authority back to the backend driver. A nonterminal successor retains its ordinary home state and needs admission again before step or run can advance it; yielding does not mean final delivery.

Public inject prepares an unexecuted tooling configuration under this implementation’s execution guard, because allocation mutates the serial concrete store. Unassociated entry during an active execution fails before allocation. This guard is coordination for the current representation, not evidence that preparing a configuration is itself an ordinary native transition. evaluate keeps preparation, execution and export inside one guard and budget. Raw backend helpers remain subject to caller coordination; this is not a generally thread-safe backend API.

Addresses and Allocation

Store separates Value(VMValue) and Continuation(ContinuationFrame) entries. ConcreteStore uses packed entry storage, a logical-handle-to-position map and fresh increasing identifiers. Reads return one entry; concrete join rejects conflicting entries. Address reuse is not a supported abstract execution mode. Concrete addresses are internal and are never required by source programs or boundary clients.

The native collector traces at complete configuration boundaries when occupancy reaches 75% of an elastic entry budget (16,384 initially; backend-configurable threshold from 70% to 80%). It compacts live entry references while preserving logical handles and Java object identity. The GarbageCollector interface separates policy from VM reference enumeration. This is storage compaction, not a replacement for the Java collector that manages the underlying objects. The native collector currently runs serially at safepoints; the execution agreement permits other correctly coordinated refinements, including concurrent collection. See native heap collection for roots, boundary retention, measurements and limitations.

Backend-only root provenance, shortest retention paths and Graphviz snapshots share the collector’s root enumerator and graph tracer. Graph snapshots can start at the complete root set or selected addresses, including an idle seed before any execution configuration exists. Reports are non-owning observations rejected by the public boundary; no language selector or activation API is added. Audited field signatures, randomized graph oracles and GC-on/off execution comparisons guard coverage. See graph hardening for guarantees and limits.

Values

Runtime Object Representation describes objects, classes, contributions, scopes, caches and occurrence layouts. VMUninitialized is an allocated backend sentinel, corresponding to the reference machine’s non-value marker. Canonical null and Booleans are role references: native objects in the Current Native Seed, and Aliens in the Host Seed. Integer/string codec transport and Aliens use separate private entries; preserving host scalars selects Aliens.

Contribution declaration indexes

Immutable core mixins expose unbound declaration positions by selector and arity. Lists of up to four declarations use direct scans; larger method, member and slot lists use immutable indexes prepared on first lookup and atomically published. Concurrent first readers may prepare equivalent indexes. Entries contain spellings, arities and local integer positions, never native references or cached receivers. The original declaration lists remain authoritative and preserve order.

ObjectProtocol still walks contributions and superclasses in semantic order, selects methods before members before slot accessors within a contribution, and binds the result to the current receiver and exact application occurrence. Physical slots are resolved through that receiver’s layout. Mutable callable eligibility is checked on each invocation. This is not a polymorphic inline cache, and neither Alien resolution nor lexical receiver selection is bypassed.

Prepared binding metadata

Function syntax owns reusable immutable parameter slot declarations, prepared on first invocation (with a shared empty case); let syntax owns reusable binding declarations and step-to-slot positions. An immutable parameter record keeps its layout and validation result together. Structural name checks are prepared with that metadata but reported only at the existing function invocation or let evaluation point. Unused malformed raw core code therefore does not fail just because its metadata was prepared. Surface syntactic checks retain their separate earlier validation contract.

Every call and let evaluation still creates fresh activation storage. Captures, return homes, uninitialized values and ordered evaluation are unchanged. Shared metadata contains no activation or world reference. Graph inspection traces cached parameter metadata without preparing unused functions. Generated expressions retained by prepared slots participate in the native graph scan and startup pointer repair. This is a representation refinement of the binding rules, not a new scope model.

Non-local return scans for its exact home before mutating liveness. Completion, failure and unwind retire homes and abandon pending member realization. Java callbacks start separate native continuation chains; their active foreign context provides the barrier required by the default boundary agreement.

State Transitions

Class realization installs generated CoreUserFunction bodies. Primary new uses ordinary method dispatch; private allocation/calls/writes/phase transitions are implemented by ConstructionCode and the same visitors. CoreObjectLiteral retains a zero-formal, factory-free CoreClassLiteral, including its contributor targets and argument routes. Evaluation sends exact new/0 to that class expression, reusing ordinary realization, dispatch and generated construction. No object-specific construction operation or continuation is needed. Empty private-call argument lists still schedule machine steps. The representation and operation rationale are in Private Construction Code.

Explicit Store: The Key Commitment

A VMObject contains a mutable ValueRef[]; a slot holds a reference rather than a separately allocated binding cell. Initialization, setters, caches and home retirement mutate backend objects. Configurations share RuntimeWorld: retaining an earlier configuration does not preserve an earlier store state. Only reachable native entries survive a collection. Active and synchronously suspended configurations, seed objects, boundary handles and explicit backend root leases define reachability. Backend tools retaining a configuration or raw address across other executions must use world.nativeHeap().retain(...) and close the lease when finished; a Java variable alone is not a native heap root. Root registration and lease release must themselves occur under the current guard or while the runtime is exclusively idle. These backend helpers do not acquire coordination internally; leases protect reachability rather than authorizing execution or concurrent store access. Boundary roots follow the lifetime agreement: open invocation attachments, host/detached receipts, public references and admitted uses retain native referents. Canonical Expat proxies and identity caches supply no independent root. Alien wrappers follow ordinary native reachability; collection drops their Java payload holds without inspecting foreign graphs. Collection preserves captured lexical data and retired return-home state, without restoring return authority or introducing activation reflection.

Staged Seed Construction

RuntimeSeed.host(store) publishes the structural Host Seed directly. RuntimeSeed.create(store) loads the parser-independent CurrentNativeSeed module definition with the compatibility boundary profile. RuntimeSeed.currentNative(store, profile) selects another boundary profile with that same native module. These are host construction choices; no language capability can reseed a published runtime.

RuntimeSeed.fromModule(store, module, profile, arguments...) accepts an ordinary core module definition and explicit constructor arguments. The fromNativeModule convenience entry supplies the narrow root identity service as its sole argument; parser integration lowers current-native-seed.vh and exercises that same installer. The parser-independent definition keeps the dependency-free bootstrap checks available; it does not install singleton method records by a separate semantic path.

Public source clients select the same choices through BootstrapRuntime(capabilities, profile), BootstrapRuntime.fromSeedModule(source, profile, capabilities, inputs...), or BootstrapRuntime.fromNativeSeedModule(source, profile, capabilities). The last entry grants the narrow identity service explicitly; the generic entry grants only its supplied inputs. Tooling capabilities are assembled after adoption and are not lent to the seed module’s definition scope.

The builder owns a private unpublished world through module construction, exact-once discovery, validation, reference substitution, obsolete boundary-owner retirement and forced collection. It returns only a completed world. Failure closes provisional access and returns no usable partial world. Platform assembly occurs after this step. The full installation invariants are in Program Structure.

Module Entry

BootstrapRuntime.instantiateModule checks a class literal’s declared arity and module restrictions, evaluates it in a fresh empty top activation, then uses an exact Expat new send. Definition, construction and synchronous callbacks share one transition budget. It returns an ExpatReceipt; the host explicitly sends any entry message and closes its receipt when finished. The intermediate class receipt is released after construction. Host sends contribute an empty caller scope.

BootstrapRuntime.evaluate is the distinct expression harness, using the assembled kernel as parent and receiver. Its supplied capability context may become part of returned closures/classes. The normative isolation contract is in Program Structure; the richer contexts are described in Tooling.

MinimalRuntimeWorld installs ordinary immutable bundle slots named null, true, false and Object, holding the corresponding seed identities. Additional supplied capabilities cannot replace those slots in this assembler. These are this tooling bundle’s assembly rules, not reserved language names; nearer declarations can shadow its slots through ordinary lexical lookup. Normal modules do not receive these bindings implicitly.

Java Boundary

Runtime diagnostics

Missing-selector errors say Message not understood: selector/arity and describe an available receiver using native class names, lambda arity, or the foreign Java type (host null is identified explicitly). An unresolved implicit send instead reports that no eligible receiver was found in lexical scope. Descriptions never send toString, inspect slots, or retain the receiver in the diagnostic. Foreign receiver types may declare inert @ForeignProtocol selector/arity data; a final miss can list up to eight other declared arities of the same selector. These declarations are hints, not dispatch authority. Java methods alone are not evidence of adapter selectors. Capture never probes nearby arities, invokes metadata providers, or retries a resolver or selected operation. No language-level doesNotUnderstand interception is implemented.

BoundaryException.diagnostic() returns immutable Diagnostic data: the existing failure kind and short message, a stable reason, an optional source site, semantic trace and related declaration/observation sites. Native reads, returns, construction, unsupported features and limits have specific reasons. Legacy constructors and kind() / getMessage() remain supported. A diagnostic retains no host exception cause, native value or execution configuration.

Named source-entry overloads on BootstrapRuntime preserve a source label and revision digest in an optional SourceMap, separate from executable core nodes. Compilation projects parser/lowering evidence into copied scalar SourceOrigin records and explicitly transfers this table to the runtime. The runtime owns weak identity associations, not source snapshots, surface trees or ANTLR data; escaped core code keeps its evidence available after later evaluations without making unreachable code a metadata root. The same core tree can execute in a world with no evidence and must produce coherent source-free diagnostics.

Sites use zero-based lines and UTF-16 columns with exclusive ends, matching the shared source basis. Optional bounded excerpts are copied during compilation and rendering never reopens source files. Generated code may inherit supplied declaration evidence; shared singletons remain unattributed. Missing evidence is reported explicitly, never fabricated from AST strings or another execution’s source. Metadata does not change execution, effects, transition budgets, failure kinds or cleanup.

The bootstrap CLI prints defined runtime failures to stderr and exits with status 1. It renders detached diagnostic data rather than a Java exception stack. --diagnostics=semantic is the default; --diagnostics=vm-developer additionally prints private physical frames, addresses and implementation names. --trace-frames=N selects a nonnegative frame limit, default five; --trace-frames=all requests the complete trace. --no-source-excerpts omits copied snippets. Parser/source-check failures remain a separate frontend path.

DiagnosticFormatter.summary provides one escaped line; format adds locations, optional excerpts, semantic frames and boundary markers. Missing locations and excerpts are explicit. Rendered labels are bounded to 512 UTF-16 units and messages/excerpts to 4096, including a visible truncation marker when needed; the structured data and legacy short message remain intact. Rendering escapes controls and preserves Unicode boundaries. The editor adapter accepts only matching source revisions and does not introduce execution on editing.

DiagnosticOptions on the source runtime configures native capture and persists for later Expat calls. DISABLED preserves execution and explicitly supplied foreign evidence while omitting native enrichment. Method/lambda/factory and initializer frames describe actual invocations, without let-scope frames. Finite capture bounds both diagnostic scanning and output; truncation is explicit. Semantic cleanup always covers every affected continuation. Repeated access to a failed member realization retains its original trace and adds the new access as related evidence, without retrying realization.

Developer reports contain detached scalars and remain backend-private. They are available through the explicit tooling entry and are rejected by the value boundary; callbacks preserve public evidence without exporting physical VM frames. Step exhaustion remains LANGUAGE_FAILURE; callback-depth and admission limits remain EXECUTION_POLICY. See the diagnostics decisions and evidence.

Boundary implementation

ForeignBoundary.identityMirror() returns a stable, boundary-owned capability. It is supplied explicitly to modules and observes identity and membership through the ordinary mirror protocol, never a special evaluator dispatch branch. The narrow root Object service shares private identity helpers without exposing the mirror. Native identity hashes follow the stable native identity; preserved foreign values use their payload identity so collecting and recreating an Alien wrapper does not change the hash of a still live foreign referent. The concrete hashing algorithm is a backend policy, not a portable identifier.

DefaultJavaBoundary owns the Alien/Expat contract. BootstrapRuntime.boundary() returns a narrow PublicFacet; package-private VmServices provisions the seed identity service. Both delegate to the same private owner. Canonical Expat and Alien indexes preserve compatible round trips without acting as native roots. Native GC reclaims unreferenced Alien wrappers and prunes their identity-cache entries, relinquishing the Java payload holds. Foreign heaps remain opaque. Startup retirement advances an export epoch, preventing old construction proxies from becoming valid under later attachments to a surviving identity.

VHExpat is the canonical proxy; a bare proxy is usable through its current invocation attachment. ExpatReceipt supplies durable lifetime evidence for checked sending and transport, independently of proxy identity. expat() returns that canonical proxy, retain() creates an independent co-hold, and idempotent close() ends only this holder’s claim. Independent host native results, including evaluation, module construction and the tooling kernel, use receipts. Host clients pass open receipts when reimporting those targets; extracting a bare proxy does not transfer the receipt’s authority.

Selected ForeignOperations default to attached arguments. The effect-free detachable(int... positions) declaration permits explicit detachment at zero-based argument positions; detachableCallbackResults() separately permits retaining callback results. ForeignCallable supplies corresponding fluent declarations. CallbackContext.detachArgument(int, VHExpat) and detachResult(VHExpat) register receipts while the authorized invocation is open, validating the supplied proxy against the authorized occurrence. An admission context alone supplies no receiver authority. ForeignOperation.retainArgument(List, int) is the simple adapter helper; non-native arguments keep their foreign/by-value transport. Its release(Object) helper closes a native receipt only, never an unrelated resource.

Callback native results attach to the enclosing NF invocation. A worker combines its CallbackContext with an attachment or uses the send(ExpatReceipt, ...) overload. Callback admission, receipt validity and return-home liveness remain separate checks. EXPIRED_ATTACHMENT, RELEASED_RECEIPT and UNDECLARED_DETACHMENT use OWNERSHIP; admission uses EXECUTION_POLICY and dead-home failure uses LANGUAGE_FAILURE.

Host/detached receipt records and admitted-use holds are the actual roots. Java Cleaner assistance may eventually release an unreachable host receipt, without its cleanup registration strongly retaining the receipt. Explicit close ends the hold deterministically. Released receipt records retain no native target graph. This is local retention management, not cross-boundary cycle collection: otherwise unreachable native/foreign cycles remain legal and conservatively retained until an edge is released or a future cooperating collector can prove them unreachable.

Integer/string interning is a non-owning native cache: collection removes cache entries whose native transport values were reclaimed. An open public boundary reference retains its value until close(); ForeignBoundary.Reference is AutoCloseable. Conversion by value does not promise host identity.

The selected boundary profile defines conversion. NATIVE_VALUES maps exact native null/Boolean identities to Java null/Boolean without Expats. Byte, Short, Integer and in-range BigInteger normalize to Long; Long and String use by-value transport. Other numeric forms are rejected by that codec. HOST_VALUES preserves host null, Booleans, numbers, and strings as Aliens. HOST_SCALARS combines native null/Boolean conversion with preserved host numbers and strings. Preservation supplies foreign identity, not Java reflection or native class dispatch. Raw VM representation values are rejected by all profiles. See Possible Seeds and Worlds for the corresponding seed choices.

For the specified callback admission protocol, DefaultJavaBoundary.Call records the suspended configuration, parent call, originating thread, admission state and active callback count. NativeHeap transition leases root suspended configurations until their native thread resumes; closed calls clear their configuration and ancestry references. Control.ForeignCall retains the selected Alien receiver as well as arguments; native tracing follows both. The receiver’s adapter hold therefore survives selection and active invocation even when the selected operation does not capture the receiver in its Java closure.

CallbackContext.send uses a permit to serialize native execution and short representation-sensitive services. invoke releases permission around the selected foreign operation and reacquires it before result conversion. Selection retains native permission and prohibits callbacks. Worker callbacks run on their own host thread, so the blocked caller needs no callback pump. The coordinator’s native owner, active call and idle state collectively realize conceptual token ownership; neither copied contexts nor nested permits are individual tokens.

The innermost call admits callbacks and completion waits for admitted descendants, as required by the contract. The implementation uses wait/notifyAll, with no FIFO or fairness guarantee. Waiting admission can be interrupted with EXECUTION_POLICY; required caller restoration waits without abandoning native state and preserves the thread’s interrupt flag. No foreign-thread affinity or termination guarantee is added. The shared guard also protects this concrete store’s representation-sensitive operations; it is an implementation constraint, not a universal physical-memory token rule.

The immutable ExecutionPolicy is selected before a BootstrapRuntime is published. Its positive maxSteps bounds each independent Expat send and source service entry; the default remains 100,000 native transitions. An embedding application can explicitly select a larger finite limit through the runtime constructor. Existing host evaluate and instantiateModule calls retain their explicit per-entry limits. Nested imports and callbacks consume the caller’s remaining transitions, including after a foreign operation handles exhaustion; they never receive a new allowance. The limit does not count source compilation, foreign I/O or time spent in foreign code.

The callback nesting limit is 64; pending requests do not consume nesting depth. The default no-crossing NLR agreement is implemented by checking home liveness and the callback continuation, then delegating crossing rejection to DefaultJavaBoundary.nonLocalReturnFailure(). Control.Error aborts the callback and retires its homes before the boundary exports the specified diagnostic. The shared Execution retains only the step budget, not a sticky failure marker; foreign recovery does not replenish it. Exhaustion prevents further native transitions without vetoing a terminal foreign result that needs no further step. Host exception classes and message text are not language interfaces.

Stack Safety

The native driver loops over explicit frames, so language method/lambda calls and nested initializers do not recursively call the Java evaluator. Synchronous foreign calls and callbacks do use the host stack. A transition budget cannot preempt a blocking foreign operation; termination remains an adapter concern. The callback limit, retained allocations and possible resource exhaustion prevent any claim of unlimited execution.

Refinement of the Formal Machine

A refinement relation must decode addressed frames and suspended Java calls into the reference stack; map mutable entries to the current σ; and preserve scope, occurrence, cache, H, B and active failure control. The allocated uninitialized sentinel maps to the private marker. Fresh identities and physical slot positions may be renamed while preserving identity, sharing and logical mappings.

The member binding’s private unrealized/realizing/realized/failed states decode directly to the formal cache’s absent/busy/ready/failed cases. Its shared identity connects cache entries and addressed completion frames; idempotent abandonment adds no retry or extra language effect. Detecting a reentrant cycle and abandoning the owning attempt remain distinct operations.

Class assembly installs a complete definition whose ordered contributions, superclass, routes, logical layout and generated coordinator decode to one formal realized-class record. Private snapshot preparation is administrative work inside a transition; no source-visible partial class or extra target/argument evaluation is introduced. Startup can replace a complete snapshot under its unpublished-world contract; this does not provide persistent configurations or live class mutation.

It must reconstruct control ownership from the coordinator according to runtime admission. Representation maintenance may stutter; declared interventions would need their specified effects in the target relation. The present refinement target includes neither a parallel execution agreement nor an independent intervention relation.

Object’s absent superclass uses the field-specific Top decoding.

Administrative steps may stutter, and one foreign Java call can contain many native callback steps. Neither fact permits hiding effects, changing failure kinds, replaying selection or ignoring divergence. A comparison must include the prototype’s scalar subset and execution limits, or explicitly exclude runs that hit them. No simulation proof is claimed; the formal appendix records the remaining obligations.
